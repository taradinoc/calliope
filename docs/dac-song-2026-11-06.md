# Dense song DAC servicing, November6

Bonk2Gen music02 exposed DAC pitch drift in pure Z80 mode. Every drum note
selects the same note108 and3496Hz source rate for its sample. The encoded bank
contains no changing drum pitch. The authored Furnace file is unchanged.

The defect reproduces with the same song in a minimal consumer without game
rendering. FM volume/state copying, note/ownership checks and deferred register
delivery leave long gaps between DAC timer polls. An empty FIFO is not required
for this fault: a late timer poll loses an elapsed sample period, stretching PCM.
Earlier demo workloads do not establish timing for this automation-heavy song.

The driver now polls between bounded decoder/copy/ownership operations. RST30
preserves live AF when a condition or operand must survive the poll. Its helper
and the direct PSG stub use unused vector padding; the short frequency-operand
helper uses remaining code space before1B00. Unread CH scratch stores are removed.
All existing assembler memory-bound assertions still pass; the image remains8KiB.

Register delivery now enables interrupts as soon as main registers are restored.
Only alternate-register access and actual chip address/data pairs stay masked.
The video IRQ only advances the DAC and pending tick; it does not consume or
produce register-queue entries. Queue preparation therefore needs no long mask.
This avoids introducing song-clock loss while improving DAC servicing.

## Consumer evidence

Same authored bank and same Bonk2Gen C runtime, Genesis Plus GX instrumented core:

- Original2-second window rates:5893.72..6263.34Hz.
- Updated12,000-frame run:6624.38..6652.09Hz; nominal6658.38Hz.
- Zero sequencer faults and PCM underruns through multiple song loops.
- Music advances11,877 ticks over11,880 video frames after startup. The original
  driver advances5837 over5880 in the6000-frame reference; no general exact-clock
  acceptance is claimed.
- All44,932 FM/PSG writes in the6000-frame original reference match the updated
  register-sequence prefix. Clock/DAC-control registers are excluded from this
  comparison; timestamps intentionally differ.
- A minimal updated consumer measures6635.51..6655.57Hz. Residual timing error
  exists in the driver too; game bus contention is not the original main cause.
- Bonk2Gen opening/jump/later cadence remains210/80/599 with no runtime faults.

This substantially reduces the reported pitch drift. The existing strict DAC
acceptance gate remains open: worst intervals and low-rate windows still fail
its0.1% / two-period limits. Stock hardware and other emulator timing need review.
Do not describe this change as sample-accurate playback or a final driver mode
recommendation.

`tools/song_clock_smoke.py` measures the supplied ROM, without forcing audition
buttons or assuming DMA has been disabled. Example from the consuming workspace:

```powershell
python E:/calliope/tools/song_clock_smoke.py out/rom.bin --frames 12000 --output-dir out/song-clock-check
```

Use `--reference-registers previous/registers.bin` to compare unchanged source
music through the common register prefix. `--strict` additionally fails on the
strict DAC limits; omitting it reports that gate without claiming it passed.
Outputs include a small window report and compact register bytes, no full trace.
The instrumented core is the existing `out/trace-core/build/calliope_trace.dll`;
use `--core` to select another compatible instrumented build. Normal cores do
not provide these telemetry exports. PAL and timer selection are explicit.
